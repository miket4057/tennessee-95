# Tenn95

Source for tenn95.com — a searchable community archive of Tennessee license plates.

## What's here

```
index.html          Homepage
archives.html        The searchable/filterable plate archive
events.html          Upcoming events
community.html       Link to the Facebook group

assets/css/style.css  All site styling (design tokens at the top)
assets/js/site.js     Shared header/footer + analytics helper
assets/js/home.js     Homepage data rendering
assets/js/archive.js  Archive search/filter/sort/pagination
assets/js/events.js   Events page rendering
assets/img/           Logo, and synced plate photos (assets/img/plates/)

data/plates.json     Plate data — regenerated by scripts/sync-airtable.js
data/events.json     Event data — you edit this file directly (see below)

scripts/sync-airtable.js  Local script: Airtable → data/plates.json
```

No sample/placeholder data is baked in anywhere — both JSON files start
empty, and every page has a real empty state for that.

## Running it locally

Because the pages fetch `data/plates.json` etc. via JavaScript, opening
`index.html` directly in a browser (`file://...`) won't work — browsers
block that for local files. Use a local server instead:

- **VS Code**: install the "Live Server" extension, right-click
  `index.html` → "Open with Live Server"
- **Or**, from the project folder: `npx serve` (requires Node) and open
  the URL it prints

## Adding plates (Airtable sync)

1. Add/edit plates in Airtable as usual.
2. One-time setup:
   ```
   cd scripts
   npm install
   cp .env.example .env
   ```
   Fill in `.env` with your Airtable Personal Access Token, Base ID, and
   table name (see comments in `.env.example` for where to find these).
3. **Before your first real sync**, open `scripts/sync-airtable.js` and
   confirm the `FIELD_MAP` block matches your Airtable field names
   exactly (case-sensitive). `Year`, `County Number`, `County Name`,
   `Colors`, and `Type` are filled in from what you told me — but
   `photo` and `serial` are my best guess at your field names and need
   your confirmation.
4. Run the sync:
   ```
   node sync-airtable.js
   ```
   This downloads any new photos into `assets/img/plates/` and rewrites
   `data/plates.json`. (Airtable's API photo links expire after ~2
   hours — the script downloads the actual files specifically so this
   doesn't bite you later.)
5. Commit and push:
   ```
   git add data/plates.json assets/img/plates
   git commit -m "Sync plates"
   git push
   ```

## Adding events

There's no Airtable table for events — add them directly to
`data/events.json` as an array of objects:

```json
[
  {
    "title": "ALPCA Tennessee Regional Meet",
    "date": "2026-09-12",
    "location": "Murfreesboro, TN",
    "host": "ALPCA",
    "description": "Annual regional swap meet."
  }
]
```

`date` must be `YYYY-MM-DD` — the page sorts and filters on it as a
plain string. Past events (date before today) are automatically hidden
from both the homepage teaser and the Events page.

## Analytics

The site uses [GoatCounter](https://www.goatcounter.com) (free,
privacy-friendly, no cookie banner needed) for hit counts and to track
what people search/filter on. Before launch:

1. Sign up at goatcounter.com and get your site code.
2. In every HTML file's `<head>`, replace `CODE` in the
   `data-goatcounter="https://CODE.goatcounter.com/count"` script tag
   with your actual code.

Archive searches are already wired to log as custom events via
`trackEvent()` in `assets/js/site.js` — worth double-checking that call
shape against GoatCounter's current docs once you're set up, since
custom-event APIs are the kind of thing that drifts over time.

## Deploying

This repo is already connected to GitHub Pages with the `tenn95.com`
custom domain (the `CNAME` file at the repo root handles that — don't
delete it). Pushing to the branch Pages is configured to serve from is
all that's needed to publish.
